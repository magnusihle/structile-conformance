# DEL-001 qualification — delivery-guardrails

**Suite DEL-001 (`delivery-guardrails` slug) verifies DEL-001** (approved task contracts),
**DEL-002** (bounded change size, incl. mechanical-PR reproduction) **and DEL-003**
(repository-neutral readiness command), gate G1. Fresh suite — no salvage source.

## Core does not implement the mechanical-reproduction clause — read this first

Core `structile` vendors `tooling/task-ready(.mjs)`, `tooling/validate-task-contract.mjs` and
`tooling/check-pr-size.mjs`, pinned from planning authority and enforced in
`.github/workflows/delivery-gates.yml`. It does **not** implement the catalog oracle's
mechanical-PR byte-for-byte reproduction clause (DEL-002: "verify that mechanical pull requests
reproduce byte-for-byte from their declared generator and input source"), at commit
`653471d73f2352a77f2cf2ef2856f6f9e17873d1` **or current core `main`**. Confirmed by inspection:
`task-ready.mjs`'s only `generatedPaths` handling exempts matching paths from the line-count
budget — it never runs a generator or diffs output. `check-pr-size.mjs` has no `generatedPaths`
concept. No regenerate-and-diff tool exists anywhere (grepped `tooling/`, `delivery/`, `docs/` for
`generator|mechanical|byte-for-byte|reproduce`; only the operating model's prose definition hits).

Per human ruling (oracle-first, same posture as HAR-004): the suite asserts the **full** oracle,

core vendors it like the other four tools** — the second should name DEL-001 as its protected test.

To qualify the suite, this report runs it against a **reference candidate**: core at `653471d`
plus one new file, `tooling/verify-mechanical.mjs`, implementing the behavioral capability the
oracle demands (`{ generator, outputs }` in, `{ reproduced, mismatches }` out — regenerate,

## Suite design

Every probe exercises the candidate's vendored tooling against synthetic scenarios in throwaway
`mkdtemp` sandboxes, never the candidate's own repository state.

- **task-ready fail-closed (DEL-001, DEL-003).** Control (valid contract, in-scope change) plus
  one isolated violation per scenario: nonexistent task id; three schema violations (missing
  `budget`, malformed `baseCommit`, missing `owner`); a diff outside `allowedPaths`; a diff over
  budget; a contract modified after `baseCommit`. Run as the real `./tooling/task-ready` entry
  point (DEL-003, exec bit asserted directly), not an internal helper.
- **check-pr-size ceilings (DEL-002).** Within-budget, over-500-lines, over-10-files, against the
  real `tooling/check-pr-size.mjs`, independent of any per-contract budget.
- **Vendored-tooling integrity (DEL-003), candidate-independent.** The four pinned tools' bytes
  hashed against constants hardcoded in the suite (pinned from
  `structile-planning@f2fc9327bd22f382d4d269ac45b5b1d9ccbb78ed`, the lineage
  `architecture/planning-inputs.lock.json` already trusts), never a candidate-derived value.
  Collected early, asserted **last**: three of the four pinned files are what the behavioral
  probes exercise, so a fail-fast hash assertion would mask which specific probe a logic
  regression should have tripped (caught during this qualification's own Mutant 1, fixed before
  the suite was considered ready).
- **Never-evidence marking (DEL-003).** Control stdout must say "Advisory only — not evidence..."
  and must not be machine-parseable as JSON.
- **Mechanical-PR reproduction (DEL-002), oracle-first.** Capability presence first, then four
  behavioral cases against `{ generator, outputs }`: reproduces exactly (pass), drifted output
  (fail), missing output (fail), failing generator (fail). Never pins a file hash.

Delegated, not locally provable: GitHub branch-protection actually blocking a merge on a nonzero
`delivery-gates.yml` exit (same class of gap HAR-003 names). Asserted instead: the exact commands
`delivery-gates.yml` runs are the same commands this suite drives against the candidate's real
entry points, and that they genuinely fail closed.

## Negative mutants

Each applied to a fresh throwaway worktree, confirmed via `git diff` to have actually applied
before running (checked explicitly every time, per repair-loop guidance), removed after.

**Mutant 1 — task-ready's out-of-scope check neutered.** `tooling/task-ready.mjs` (worktree of
`653471d`): the `allowedPaths` violation push guarded with `if (false && ...)`.
`measurements.error: "diff touches a path outside allowedPaths: must fail closed"`. Fails for the
asserted reason: with the check neutered, the out-of-scope scenario's `task-ready` reports ready
(exit 0) instead of failing, and the assertion catches exactly that. (Edits a hash-pinned file, so
vendor-hash integrity would also catch it — but it runs last, so this specific behavioral
assertion is what actually fires, proving it independently load-bearing.)

**Mutant 2 — check-pr-size ceiling raised.** `tooling/check-pr-size.mjs` (worktree of `653471d`):
`HARD_MAX_LINES` raised `500` → `5000`.
`measurements.error: "exceeds the 500-line ceiling: expected check-pr-size to fail closed"`. Fails
for the asserted reason: the 600-line scenario now exits 0 with the raised ceiling.

**Mutant 3 — vendored tooling drifted from canonical.** `tooling/validate-task-contract.mjs`
(worktree of the **reference overlay commit**, not bare `653471d` — see note): trailing
`// drift` comment appended, changing bytes without changing behavior.
`measurements.error: "vendored delivery tooling must byte-match the planning-pinned canonical source"`,
with `actual`/`expected` digests for exactly `tooling/validate-task-contract.mjs`. Fails for the
asserted reason: behavior is unchanged, so every behavioral probe passes and only the deferred
vendor-hash assertion fails, on exactly the drifted file. (First attempted against bare
`653471d`, which lacks `verify-mechanical.mjs`; that failed on capability-presence before ever
reaching the vendor-hash check, proving the wrong thing — rebuilt on the reference overlay commit
to isolate this clause.)

**Mutant 4 — reference overlay's mismatch detection neutered.** `tooling/verify-mechanical.mjs`
(worktree of the reference overlay commit): the byte comparison guarded with `if (false && ...)`.
`measurements.error: "drifted output: reproduced must be false"`. Fails for the asserted reason:
the "drifted output" case commits `output/generated.txt` as `"HAND EDITED"`; with detection
neutered, the tool reports `reproduced: true` regardless, and the assertion catches exactly that
boolean. This is the mutant the human ruling specifically asked for.

Each mutant targets a distinct clause (task-ready scope enforcement, check-pr-size ceilings,
vendored-tooling integrity, mechanical-reproduction fail-closed behavior) and each failed
specifically on the mechanism exercising that clause. No mutant was non-viable.

+#!/usr/bin/env node
+// Reference implementation, DEL-002 mechanical-PR verification (follow-up
+// task, not yet part of core main): given a task contract's declared
+// generator command and its declared output paths, regenerate and byte-diff
+// against the working tree. Fails closed on any mismatch, a failing
+// generator, or a declared output the working tree does not have.
+//
+// Advisory convergence tooling only, in the same spirit as task-ready
+// (DEL-003): a clean result here is never release evidence.
+
+import { execSync } from "node:child_process";
+import { existsSync, readFileSync } from "node:fs";
+import { resolve } from "node:path";
+
+export function verifyMechanicalReproduction({ generator, outputs }, repo = process.cwd()) {
+  if (typeof generator !== "string" || generator.trim().length === 0) {
+    throw new Error("verify-mechanical requires a non-empty generator command");
+  }
+  if (!Array.isArray(outputs) || outputs.length === 0) {
+    throw new Error("verify-mechanical requires at least one declared output path");
+  }
+  const before = new Map();
+  for (const output of outputs) {
+    const path = resolve(repo, output);
+    if (!existsSync(path)) return { reproduced: false, mismatches: [`missing declared output: ${output}`] };
+    before.set(output, readFileSync(path));
+  }
+  try {
+    execSync(generator, { cwd: repo, stdio: "pipe" });
+  } catch (error) {
+    return { reproduced: false, mismatches: [`generator failed: ${generator} (${error.message.split("\n")[0]})`] };
+  }
+  const mismatches = [];
+  for (const output of outputs) {
+    const path = resolve(repo, output);
+    if (!existsSync(path)) { mismatches.push(`generator did not produce: ${output}`); continue; }
+    if (!readFileSync(path).equals(before.get(output))) {
+      mismatches.push(`regenerated output differs from committed content: ${output}`);
+    }
+  }
+  return { reproduced: mismatches.length === 0, mismatches };
+}
+
+const invokedDirectly = process.argv[1] && import.meta.url.endsWith(process.argv[1].split("/").pop());
+if (invokedDirectly) {
+  const specPath = process.argv[2];
+  if (!specPath) {
+    console.error("usage: verify-mechanical <spec.json> [--repo <dir>]");
+    process.exit(2);
+  }
+  const repoIndex = process.argv.indexOf("--repo");
+  const repo = repoIndex >= 0 ? resolve(process.argv[repoIndex + 1] ?? ".") : process.cwd();
+  const spec = JSON.parse(readFileSync(resolve(repo, specPath), "utf8"));
+  const { reproduced, mismatches } = verifyMechanicalReproduction(spec, repo);
+  if (!reproduced) {
+    for (const mismatch of mismatches) console.error(`FAIL ${mismatch}`);
+    console.error("verify-mechanical: NOT reproduced");
+    process.exit(1);
+  }
+  console.log("verify-mechanical: reproduced byte-for-byte. Advisory only — not evidence.");
+}
