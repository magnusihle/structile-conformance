## Negative mutants

Built in a throwaway worktree of core (`git worktree add ... 653471d7...`), one mutation at
a time, rebuilt (`npm run build --workspace <pkg> && npm run build:catalog`), rerun, then
reverted (`git checkout --`) before the next mutant. Worktree removed with
`git worktree remove --force` after all three.

**Mutant 1 — forbidden style value (token-lint).** `packages/tokens/src/validation.ts`:
removed the `["url-function", /url\s*\(/i]` entry from `FORBIDDEN_VALUE_PATTERNS`, so the
candidate's own value scan no longer blocks a `url(...)` payload on the one category
(`elevation`) with no grammar to catch it independently.

```
{"testId":"DS-001","status":"failed","exitCode":1, ...}
measurements.error: "token-lint:url-function:elevation.000 was accepted but must be rejected"
```

Fails for the asserted reason: the suite's `assertDiscriminates` probe expected
`validateTheme` to reject the poisoned theme and it did not.

**Mutant 2 — removed catalog registration guarantee (duplicate ID).**
`packages/catalog/src/validation.ts` `buildCatalog`: removed
`if (seen.has(registration.id)) violations.push(...)`, so two registrations sharing an ID
build successfully instead of being rejected.

```
{"testId":"DS-001","status":"failed","exitCode":1, ...}
measurements.error: "catalog:duplicate-id was accepted but must be rejected"
```

Fails for the asserted reason: DS-003's stable-ID guarantee is no longer enforced by
`buildCatalog`, and the suite's dedicated duplicate-id probe catches exactly that.

**Mutant 3 — disallowed theme override (tenant scope escape).**
`packages/tokens/src/validation.ts` `validateThemeOverride`: removed the
`scope === "tenant" && !tenantOverridableTokens.includes(id)` branch, so a tenant-scoped
override can touch any token, not just the declared allow-list.

```
{"testId":"DS-001","status":"failed","exitCode":1, ...}
measurements.error: "theme-override:tenant:color.surface.sunken was accepted but must be
rejected"
```

Fails for the asserted reason: the suite probes every non-overridable token (bounded to 25)
and expects each to be denied at tenant scope; with the check removed, a non-overridable
token is accepted instead.

Each mutant targets a distinct DS-001 assertion class (style-value injection, catalog
identity stability, tenant override scope) and was confirmed to fail specifically on the
probe exercising that class, not incidentally elsewhere.
