# DEL-002 qualification — self-check

**Fresh suite, no salvage source.** This is the last of the non-heavy re-cut suites and the only
one that is meta: DEL-002 verifies the runner's own `run-subset` unsigned-subset machinery and
the evidence gate's fail-closed behavior, by driving the CLI as a subprocess (as any real caller
would) rather than by importing a candidate-built package. Suite ID DEL-002 (`self-check` slug),
gate G1, requirement DEL-004. Catalog command (`verification/test-catalog.json`, amended in
planning#11 specifically so this suite could pass):

> `platform-conformance run self-check` — "The suite's own envelope is signed and authoritative.
> Internally it invokes named-subset unsigned runs and asserts: the subset executes exactly the
> requested tests; every internally emitted envelope carries localUnsigned true; and the
> evidence gate rejects localUnsigned or malformed envelopes as authority for any requirement or
> gate claim."

## What "signed and authoritative" means here, precisely

The oracle sentence describes DEL-002's envelope **at protected-workflow dispatch time**, not at
local qualification time. `runnerDigests()` (`src/evidence.ts`) sets
`measurements.localUnsigned = !process.env.STRUCTILE_RUNNER_IMAGE_DIGEST` — every local
invocation, of every suite, is unsigned regardless of the catalog's wording, because
`STRUCTILE_RUNNER_IMAGE_DIGEST` is only ever set by the protected workflow after it has pulled
the pinned, attested runner image. Only a run dispatched from that protected workflow, against
the candidate's pinned commit, produces an envelope where `measurements.localUnsigned` is
`false` and `provenance.workflowIdentity` names the protected workflow rather than
`local-unsigned/not-release-evidence`.

So: every run below is local and informative. `measurements.localUnsigned: true` on DEL-002's own
envelope in this qualification is correct and expected, not a defect — it will read `false` only
when the protected G1 workflow runs it. Do not read a local `passed` status on this suite, or any
suite, as G1 evidence.

## Design: candidate is a pure pass-through

Every other candidate-dependent suite in this repo (`architecture-boundaries`, `design-system`,
`package-matrix`, …) makes specific assertions about the contents of `candidate` — it is the
subject under test. DEL-002 is not testing a candidate; it is testing the **runner itself**. Its
`candidate` parameter is used for exactly one thing: it is forwarded, unexamined, to the
`run-subset` invocation the suite drives internally, because `run-subset` (like `run`) requires
*some* valid Git repository to build a `candidate` identity block from. self-check makes no
assertion about what that repository contains.

This means DEL-004's oracle — "the subset executes exactly the requested tests" and "every
internally emitted envelope carries localUnsigned true" — is provable **independent of whether
the inner suites pass or fail against whatever candidate self-check happens to receive**.
`buildEvidence` marks an envelope `localUnsigned` and writes it to disk on suite success,
suite-assertion failure, *and* suite crash alike (`src/cli.ts` `runSuite`'s try/catch always
reaches `buildEvidence`). The qualification run below demonstrates this directly: with a real
candidate, one probed suite passes and the other fails, and both envelopes are still
`localUnsigned: true`, and `run-subset`'s subset-selection guarantee holds regardless.

### Probe slugs

`PROBE_SLUGS = ["architecture-boundaries", "open-source"]` — chosen over the task brief's
example (`architecture-boundaries`, `design-system`) because both are pure filesystem probes
against `candidate` with no subprocess of their own (no `npm run build`, no docker, no external
checkout), so the nested `run-subset` invocation is fast and deterministic whatever candidate is
supplied. `design-system` requires `buildAndImport` (an `npm run build --workspace` call) inside
an already-nested subprocess, which is unnecessary weight for what this probe needs to prove.

## Mutants

There is no separate "candidate" to mutate for a suite that tests the runner itself, so — per the
task brief's explicit guidance for this case — the mutants below patch the runner's own oracle
machinery (`src/cli.ts`, `tooling/validate-planning.mjs`; neither is a protected path) one at a
time, in this worktree, each reverted with `git checkout --` and confirmed clean
(`git status --porcelain`) before the next was applied. All three were re-run after the rebase
onto `4975300`, against the same clean candidate `c00a79c…` as the positive control; the
assertions each mutant trips are quoted verbatim below.

**Mutant 1 — the evidence gate stops failing closed on type confusion.** `src/cli.ts`,
`verifyEvidence`: changed
`if (localUnsigned !== undefined && typeof localUnsigned !== "boolean")` to
`if (localUnsigned !== undefined && typeof localUnsigned !== "boolean" && !localUnsigned)`, so a
truthy non-boolean (`"true"`, `1`) would pass instead of being rejected. Re-ran the positive
control; DEL-002 now correctly fails, catching its own regression:

```
verify-evidence must reject localUnsigned:string-true
```

**Mutant 2 — `run-subset` no longer executes exactly the requested suites.** `src/cli.ts`, the
`run-subset` loop: changed `for (const slug of slugs)` to
`for (const slug of [...slugs, slugs[0]])`, so one extra suite runs beyond what was requested.
Re-ran; caught:

```
run-subset must emit exactly one result line per requested suite, no more and no fewer

3 !== 2
```

**Mutant 3 — the evidence schema stops catching a missing required field.**
`tooling/validate-planning.mjs`, `validateEvidence`: changed
`if (!test) errors.push(...)` to `if (!test && evidence?.testId !== undefined) errors.push(...)`,
so an envelope with `testId` entirely absent is silently accepted instead of rejected. Re-ran;
caught:

```
verify-evidence must reject an envelope missing testId, even with --allow-unsigned
```

Each mutation was confirmed applied (`git diff --stat` — `1 file changed, 1 insertion(+), 1
deletion(-)` in every case) before the suite was re-run, and confirmed reverted
(`git status --porcelain` empty) before the next was applied. Without a mutation the same command
passes, so each failure is discrimination, not a broken harness.

## localUnsigned / informative statement

This suite's relationship to "signed" is unlike every other suite's: DEL-002 does not merely
*carry* `localUnsigned: true` locally like any other suite — it is the suite whose entire job is
to assert that `localUnsigned` marking and rejection actually work, from the outside, as a real
caller would observe them. Passing DEL-002 locally proves the mechanism it probes behaves
correctly *right now, in this worktree*; it does not and cannot prove anything about what the
protected runner image will do, because DEL-002 never runs itself inside that image locally.
DEL-004 remains unevidenced for G1 until the protected conformance workflow runs `self-check`,
signed, against the merged candidate, and produces an envelope with
`measurements.localUnsigned: false` and a real `provenance.workflowIdentity`.
